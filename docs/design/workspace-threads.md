# 项目工作区、研究分叉与成果合并

底层使用 Pi 0.85.1。研究目录关系见 [文件夹工作区](folder-workspaces.md)，会话与运行控制见 [会话管理](session-management.md)，团队消息与成员见 [研究团队](agent-team.md)。

## 对象和目录

工作区 `ResearchWorkspace` 绑定本机或 SSH 机器上的实际文件夹；旧数据的 managed 工作区继续使用应用管理的目录。同一个工作区也是一个团队，普通频道与成员私信独立于研究运行。每个研究会话对应一项 `ResearchProject`，有自己的地图、轮次、事件和 Pi 历史，并在团队实验频道投影为研究线程，没有固定项目导师或额外主会话。新研究先选择工作区、工作流、模型及可选分类，发送首条消息时创建。

`ResearchCollection` 只做手选分类，可包含不同工作区的研究；`on_board` 决定研究是否出现在看板。分类、标题和置顶不改变执行目录、研究问题或计划。

```text
<数据目录>/research-projects/<工作区id>/
  repo/                    私有 main：目录镜像、AGENTS.md、.ora/agents/、memory/、合并记录
  threads/<研究id>/        research/<短id>：代码检查点；本机分叉在此执行
<数据目录>/research/<研究id>/
  location.json            实际执行位置与来源绑定
  work -> 上述worktree     旧路径兼容链接，不代表外部研究的实际 cwd
  logs/ runs/              实验日志和指标，不进入 Git
```

普通本机研究的工具和实验在绑定文件夹执行，SSH 研究在绑定远端目录执行。检查点只把允许的普通文件复制到应用私有 Git 仓库，不自动修改用户仓库的 `.git`、HEAD 或 index。数据集、环境、依赖、权重、符号链接及超限文件不进入代码检查点；超过快照总量限制时明确失败，不伪造成功提交。远端不要求安装 Git。

分叉使用独立执行目录：本机使用私有 worktree，SSH 使用远端独立研究目录，工作区的来源位置保持不变。旧 managed 研究保留原 worktree 行为；历史目录导入不会补造各轮次的状态。

## 按轮次分叉

可分叉的研究轮次保存 `ResearchSprint.snapshot` 和匹配的 `commit_sha`。工具交接、导师判断、提炼与运行结束后的系统交接在下一轮开始前保存边界；只读 discussion 复用分支上已保存的代码检查点来封存对话快照，不对实际执行目录拍摄新的文件快照。快照包含当时的问题、背景、地图、计划、预算、事件、轮次摘要和数据集来源。Git 失败时原交接仍保存，并记录检查点不可用；这样的轮次不能分叉。

- `GET /research/projects/{id}/forks/options` 列出可选轮次及不可用原因。旧数据缺少真实历史快照时不可分叉；正在收尾的轮次也不可选。
- `POST /research/projects/{id}/forks` 接收 `sprint_id`、`expected_commit`、`change` 和幂等 UUID `client_id`。
- 新 worktree 从该精确提交创建；地图节点另分配 ID，源状态和代码不受影响。
- `parent_id` / `forked_from` 记录原研究、会话、轮次、提交和新方向。继承历史存入独立的 `inherited_history`，界面只读展开。
- 历史证据保留最初研究、节点和日志来源；不会把原作业重新派发到子研究。原审批、旧预算消耗和活动队列不复制为新任务。
- 子研究先处于 `scoping / paused`。继承计划仅供参考，清除批准时间并标记 inherited；继续定题、生成新计划并经人批准后才能实验。新研究的根节点在新计划批准时重新打开。

数据库锁按会话（多个时按 ID 排序）→ 工作区的顺序获取，与归档和调度一致；仓库写入另持有工作区 Git 锁。创建失败时回滚领域对象并清理属于新研究的 worktree；重试同一请求返回同一分支。

## 成果预览和合并

结论与代码分别预览、分别确认。新预览和正常应用要求研究暂停或完成，且没有活动轮次或实验；归档工作区和会话禁止写入。共享外部文件夹里的其他研究也不能正在运行。私有主仓库和源研究 worktree 均需保持检查点已保存。

- `GET /research/projects/{id}/merge-options` 给出可用操作和原因。
- `POST /research/projects/{id}/merge-preview`：`kind=memory`，或 `kind=code` 加可选 `paths`。
- `POST /research/projects/{id}/merges/{merge_id}/apply`：提交预览中的 `expected_main_commit` 与 `expected_source_commit`，确认后才应用。
- `POST /research/projects/{id}/merges/{merge_id}/cancel`：取消未应用预览。
- 项目级 `GET /research/workspaces/{id}/merges` 和 `/memory` 供成果页展示历史、提交及研究来源。

结论必须已经确认，且存在带来源的证据；系统从记录生成 `memory/<完整研究id>.md`，展示结论、条件局限、代码检查点和原始证据来源后确认写入，无额外模型调用。后续研究的定题、讨论、执行者和导师简报读取私有 main 上已提交的成果，注明这是受证据和条件限制的历史资料，不能视为新的指令或实验授权。未合并分支及未提交修改不会进入记忆上下文。

模型上下文只读取有上限的普通 UTF-8 记忆文件；成果页独立读取完整列表，可分页，不套用模型的文件数和文本总量限制。记忆正文的 `commit_sha` 指当前读取版本，`merge_commit_sha` 单独保留原合并提交。

代码合并以共同祖先到源提交的所选文件差异做三方应用，保留文件原路径，从而保留导入关系和冲突判断；不自动移动到 shared/。`AGENTS.md`、兼容旧 `PROJECT.md` 与 `memory/` 不能被代码合并覆盖。外部目录预览先刷新并提交私有 main 镜像，再在临时 worktree 内计算合并。冲突列出文件和差异，冲突结果不会写回实际目录或合入 main；私有基线刷新本身可能产生提交。可以取消或改选文件；修正源代码并保存新检查点后重新预览。普通研究的修改已在真实文件夹中时，预览可能没有新差异。

应用时持有工作区 Git 写锁，重新检查两端提交、目录状态和结论证据摘要，重建预览，生成提交后 fast-forward 私有 main。外部目录另检查目标位置、SSH 连接、文件内容与权限、根目录身份，再写回真实文件夹；预览后的变化要求重新预览。写回保留已有权限，失败回滚不覆盖用户后续修改；已有文件最终复核与原子替换之间仍有标准文件系统的外部写入竞态，不能承诺绝对内容比较并交换。

`ResearchMerge` 保存 preview / conflict / applied / cancelled 状态。私有提交带 `ORA-Merge` 标识，物理发布成功后另保存回执；Git 已提交但发布或数据库失败时，可从原预览恢复。尚未发布的恢复仍拒绝与活动研究并行写入；已有匹配发布回执时只回填数据库，不再次写目录。

## 通报和权限

分叉与成果合并追加原研究事件及工作区通报，不启动模型。这些通报是历史事实，不是待批准事项。通报与成果页均能回到研究来源。

按轮次分叉和应用合并由研究页的人机交互完成，不让模型自动合并代码或批准计划。研究留言、计划审批与运行控制遵守各自的状态机；不能通过通用会话复制、追加或运行接口绕过。所有接口独立验证本机模式、用户与工作区归属、归档状态和预览对应关系。

## 数据与验证

迁移 0033–0036 保存早期检查点、会话历史和运行控制；0037 添加研究来源、轮次快照及只读继承历史；0038 添加成果合并记录。0039 添加目录位置与手选分类，把旧项目导师和普通项目聊天转换为暂停研究，复用原会话及 Pi 历史，并清除固定主会话关联。老数据保持可读，缺失的历史快照不会从今天的地图补写。

后端回归涵盖精确轮次恢复、独立地图与来源、旧轮次拒绝、失败清理、幂等请求、三方合并与冲突、过期预览、目录未提交内容、Git/数据库恢复，以及真实目录写回和权限。页面验收需串联目录选择、研究分叉、成果预览确认、冲突处理与成果来源查看。共享资料库的上传和发布仍是独立后续功能。
