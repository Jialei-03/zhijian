# 设计：应用结构与交互

研究分区以团队、频道、私信和线程组织协作；研究的计划、地图、实验、证据和文件保留在研究线程中。具体路由见 `frontend/src/app/routes.ts`，团队界面见 `frontend/src/screens/research/TeamScreen.tsx`。

## 总原则

1. 界面只放名称、状态和短标签，不写引导段落、副标题说明或字段提示；实际研究内容和错误原因照常显示。
2. 操作放在对象旁边：回复与停止在消息上，分叉与合并在对应研究和变更入口，成员与规则在团队设置中编辑。
3. 加载时保留外壳、上一屏内容或骨架，不出现整页空白转圈。
4. 所有页面沿用 `frontend/src/ui` 组件与现有 tokens，中英文同步；详见 [界面规范](ui-norms.md)。

## 分区

| 分区 | 侧栏与主区 |
| --- | --- |
| 研究 | 团队切换、频道、私信、线程、提及我的、团队设置；主区为消息与研究线程 |
| 资料 | 全部、在读、未读、已读、发现和最近打开；论文列表、卡片与阅读器 |
| 定时任务 | 任务列表、新建、暂停、下次执行和详情；与团队定时规则共用调度 |
| 自定义 | 技能、工作流、机器、实验追踪、模型等已有管理页 |
| 设置 | 账号、外观与数据等设置 |

看板是研究的手选视图，不是独立任务状态中心；通知铃铛和未读标记保留来源。资料分区没有额外首页，不为尚未实现的能力添加空壳入口。

## 团队与消息

团队侧栏列出频道和成员私信，以及线程、提及我的和团队设置。频道可新建、改名、归档；成员显示空闲、排队、工作中或等你。团队设置包含成员、预算、工作流和比较；成员定义是 agent 文件，预算默认不限。

用户可一次 `@` 多个成员，不限人数；agent 交接用 `team_send_message.to`，正文 `@` 只是提到。输入框提供 `@` 补全、附件和发送；Enter 排队，⌘/Ctrl+Enter 立即发送。排队中的用户消息可编辑、撤回或升级为立即发送。私信可选模型。

消息显示作者、时间、Markdown 正文、回复和工作过程；作者名字只显示一处。排队或运行中的消息上有「停止」。线程在右侧打开，可关闭或全屏；文件卡片打开预览，跨频道结果保留来源链接。agent 主动发起「等你」只通过 `team_wait_for_owner`，正文提及负责人只通知；显式规则等待与研究审批见 [研究团队](agent-team.md)。

## 新研究与研究线程

新研究选择团队/工作区、工作流和模型，发送首条消息时创建研究。执行机器来自绑定目录；界面展示机器身份，避免把同名目录混淆。附件沿用既有上传能力。

研究在实验频道映射为线程；计划和结论卡片保留「开始实验」「接受」等操作。每轮工作过程折叠，保留最终回复；实验卡片显示机器、状态和指标，文件卡片显示变更与检查点。标题由规则生成短标题，不增加模型调用，支持人工改名。

研究详情保留重命名、暂停/继续、停止与归档；右侧按有内容的部分显示变更、子研究、实验、计划和来源。分叉必须使用已封存轮次检查点，成果合并先预览再确认。原研究链接仍可访问，研究状态机与团队消息控制的边界见 [会话管理](session-management.md)。

## 工作流与比较

列表和画布编辑同一工作流，节点打开成员私信或频道；当前规则可改，消息引用的历史版本只读。团队画布使用可用主区，管理列表沿用页面宽度 token，不新增尺寸变量。

比较页并排显示研究的结论、数字、token、时间、轮次和成员。换工作流重跑复用研究分叉，评测工作区支持问题 × 工作流矩阵；详见 [工作流](workflows.md)。

## 资料与定时任务

资料页右上角统一放搜索和「导入」；分类在侧栏，主区支持列表/卡片切换。阅读器沿用现有顶栏、侧栏与面板组件。

定时任务可在团队中新建研究或给已有研究发消息，结果保留研究和规则来源；列表与画布编辑同一规则。空状态只有图标、短标题和可执行的按钮，所有入口必须有实际行为。
