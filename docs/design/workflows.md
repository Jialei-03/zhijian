# 设计：工作流

工作流是一组「当……时，谁做什么」的规则。列表和画布编辑同一份 `Workflow`；成员、频道、规则和运行叠加数据见 [接口契约](agent-team-contract.md)，执行顺序见 [规则引擎](team-rules-engine.md)。

## 定义与执行

- 触发包括消息、显式收件人、作业完成、计划批准、提出结论、评审失败和定时；动作包括叫醒、评审、显式等负责人和发消息。
- `ResearchWorkspace.workflow` 保存团队当前定义与布局，`workflow_state` 保存规则计数、评审、阶段路由、历史版本和定时认领等状态。按工作流 ID 保留团队覆盖，切换后再切回不会丢失编辑。
- `team_workflows.py` 在团队行锁内匹配事件、保存状态、登记触发并写入成员收件箱。消息、私信隐式收件人、用户 `@` 和 agent 的 `team_send_message.to` 都走同一入口；agent 正文 `@` 不作为叫醒依据。
- 新研究默认使用团队当前工作流，研究、重跑和评测各自保存快照。切换团队工作流不改写已有研究；「换个工作流再做一遍」创建另一项研究。
- `limit.per_thread` 与评审 `max_rounds` 默认不限，缺省或 0 表示不限。用户显式填写正数才设限；agent 接力没有上限。
- 研究的计划批准、产出、检查点、实验等待和结论确认由原领域执行器保留；规则决定接下来由谁处理，不替用户批准实验。

## 内置模板

| 模板 | 协作内容 |
| --- | --- |
| 研究 | 定题、批准计划、执行、导师评审、结论确认、复盘 |
| 文献综述 | 收集来源、精读要点、综述成文、评审 |
| 复现一篇论文 | 明确复现目标、实验、对比报告 |
| 写论文 | 汇总结论、提纲、草稿、自审、确认 |
| 从读到写 | 综述、选择方向、子研究、论文 |

模板在 `backend/team_rule_templates.py`，中英文使用相同规则身份。内置模板在全局自定义页编辑时另存副本；团队当前定义可直接修改。旧线性 `steps` 只作为兼容输入，经 `convert_linear_workflow` 转为规则；原步骤产出、确认、轮数和检查点元数据仍由 `research_workflows.py` 执行，阶段路由由规则引擎维护。旧步骤轮数与评审重试默认也不限。

## 列表与画布

`frontend/src/screens/team/workflow/WorkflowView.tsx` 接收 `workflow`、`members`、`channels`、`onChange`，以及可选 `runtime`、`focusedRule`、`readOnly`、`initialView`、`hideTitle`、`onOpenNode`。组件管理视图与编辑草稿，外层负责唯一的工作流数据、版本、接口保存和错误反馈；只读模式用于历史版本。

列表支持搜索、启停、编辑、排序、删除；画布以成员和频道为节点、规则为连线，评审的主线与退回线编辑同一规则。节点位置保存在 `layout.members/channels`，定时或其他事件节点位置保存在 `Rule.position`。订阅通过 `message → wake + subscribers: true` 表达，展示当前有效订阅者，不新增动作类型。

节点统一为 168×44 的单行：小头像、名字、状态点，频道显示 `#` 与名字；详细规则在浮层或编辑器查看。尺寸与内边距组合现有 UI tokens。未保存坐标的节点从左向右分层，研究者和触发源固定在最左层，层间水平净距 120，同层垂直净距 32；已保存坐标优先，移动只保存被移动的节点。「自动整理」重排并保存全部节点。

同一有向节点对合并为一条贝塞尔边，标签按动作合并与计数，点击或按回车选择其中的规则。正向边直接连接左右两侧，标签在中点；反向边从节点底部绕回，最低点比两个节点底部的较低者多 `28 + 14×序号` 像素，序号按同一有向节点对从 1 开始，不随跨层数增长，标签在最低点。自环位于节点右下角，半径 14；不做避障路由。

首次打开、整理与「适应画布」先计算 zoom=1 下包含节点及连线的包围盒：四周预留 24px，能放下时按 1:1 居中；放不下则缩放适应，最低为 0.75，并从最左层左侧 24px 处对齐，超出部分可平移查看。左侧已放置项显示头像或频道图标，未放置项显示加号与次级文字色。

拖线先打开规则草稿，取消不保存；保存、启停、排序和布局修改通过 `onChange` 回传。`TeamSettings.tsx` 串行保存版本，避免快速连续操作覆盖；点击节点进入成员私信或频道。运行态由 `runtime.members/fired` 叠加，不覆盖布局。列表、节点、连线及布局操作均有键盘入口，界面沿用现有 tokens 与简短双语标签。

## 接口与定时

- `GET/PUT/POST /research/workspaces/{id}/team/workflow`：读取、带版本保存、切换团队工作流；版本冲突返回 409。
- `GET /research/workspaces/{id}/team/workflows/{workflow_id}/{version}`：读取消息对应的历史定义。
- `/research/workflows`：内置与用户工作流的规则定义及管理；兼容导入旧步骤格式。
- `team_timers.py` 是统一定时入口：`due()` 规划，`match()` 决策，团队锁内认领并保存。失败也推进认领时间，不重复堆积补跑。
- 旧 `ResearchSchedule` 保留新研究/现有研究的投递配置和执行历史，并同步为 `schedule:<id>` 规则；画布与定时任务分区修改同一条规则。无法用五段 cron 精确表达的小时周期保留原相位门控。

## 比较与评测

`/research/compare` 按研究 ID 返回结论、关键数字、token、作业时长、墙钟用时、轮次和实际成员参与情况；引用、转发和继承历史不重复计费。缺失数字显示 `—`，不按零处理，也不假定数值越大越好。

「换个工作流再做一遍」复用 [轮次分叉](workspace-threads.md)：从可靠检查点继承地图与代码，创建后暂停，新计划仍需人批准。评测工作区可创建问题 × 工作流矩阵并保存批次及研究引用；结果复用同一比较数据。
