# 设计：研究团队

ORA 提供研究工具，协作方式由用户和工作流决定。一个团队对应 `ResearchWorkspace`，包含成员、频道、私信、线程、工作流和项目仓库。成员定义见 [成员文件](agent-files.md)，规则格式见 [接口契约](agent-team-contract.md)。

## 对象

| 对象 | 当前实现 |
| --- | --- |
| 团队 | `ResearchWorkspace`；共享仓库、说明、成员和当前工作流 |
| 成员 | 研究者和 agent；agent 定义以项目 `.ora/agents/*.md` 为准，数据库保存身份与运行状态 |
| 频道 | 默认综述、实验、写作、闲聊；可新建、改名、归档，实验频道保留研究映射 |
| 私信 | 研究者与某个成员的消息记录，无显式收件人时由该成员回应 |
| 线程 | 根消息下的回复；研究线程引用 `ResearchProject`，以 `research:<id>` 标识 |
| 工作流 | 一组事件与动作规则；列表和画布编辑同一份数据 |

研究线程直接投影已有事件、轮次、作业和继承历史，不复制研究正文。计划和结论卡片保留原审批入口，地图、实验、文件、检查点、分叉和合并仍由研究领域管理。

## 消息和叫醒

- **用户 `@` 谁就叫醒谁，不限人数**。一次可以指定多个成员；保持用户原话，分工由消息和工作流决定。未指定成员的频道消息按规则处理，未命中规则就只保存消息。
- **agent 交接使用 `team_send_message` 的 `to`**，可同时指定多个成员；省略频道和线程时回复当前位置。agent 正文中的 `@` 只是提到，不会叫醒其他 agent；提及研究者仍可产生通知。
- 成员回复与 wake 交接跟随触发位置：顶层消息的回复留在会话里，线程消息的回复留在同一线程。用户点「回复」并发送消息才产生普通线程；研究线程沿用原行为，历史消息不迁移。
- 顶层对话的规则范围为 `[team, channel, null]`，等你、计数和交接共用该频道分区；用户新开的线程使用自己的根消息 ID。线程入口显示最近回复的去重参与者头像（最多三个）、回复数与最后回复时间。
- 发给忙碌成员时，Enter 默认排队，⌘/Ctrl+Enter 立即发送。排队记录持久化，可编辑、撤回或升级为立即发送；立即发送通过 `AgentControl` 和 Pi `steer` 送入原运行。
- 同一成员同时执行一件事。相同频道、线程、成员尚未开始的投递会合并，保留要求、附件和规则指示。
- 普通回应填充原运行的消息占位，完成后只结算、路由一次。跨频道发帖在来源消息上保留结果链接，并沿用原路由范围。
- 后台作业结束产生去重的系统消息；研究的 `waiting_on` 作业组全部完成后只发一次继续事件。
- 消息记录未读和规则来源；历史规则版本只读，当前规则可以编辑。工作过程可展开，文件卡片可打开预览。

## 等你与停止

agent 主动要求负责人决策时，唯一入口是 `team_wait_for_owner(text)`：发送问题、通知负责人并暂停当前线程，直到负责人回复。正文里的 `@研究者`、导师的普通判断或建议本身都不进入「等你」。

用户显式配置的工作流 `wait_for_owner` 动作仍会暂停路由；研究计划批准、结论确认等沿用研究审批状态机。这些显式等待不根据 agent 的措辞推断。等待期间其他成员、作业和定时事件不能解除等待，负责人在同一路由范围内回复后解除。

**停止放在消息上**：有排队中或运行中的 `AgentRun` 时，消息提供「停止」，取消该运行；尚在收件箱里的用户投递可撤回。研究的暂停、恢复、停止实验和审批继续使用研究入口，取消一条回复不等同批准计划或停止全部实验。

## 预算

| 范围 | 默认 | 用户设置 |
| --- | --- | --- |
| 成员单次运行 | 轮数、token、时长均不限 | agent 文件中的 `budget.turns/tokens/minutes` |
| 成员累计 token | 不限 | agent 文件中的 `budget.total_tokens` |
| 研究 | 轮次、token、作业时长均不限 | 研究计划与预算接口；未设置的值为 `None` |
| 团队 | 周期 token、并发数均不限 | 团队设置；`max_tokens/max_concurrent` 为 0 表示不限 |
| agent 接力 | 不限 | 无接力上限设置；需要结束时停止消息上的运行 |
| 规则次数与评审退回 | 不限 | `limit.per_thread`、`then.max_rounds`；缺省或 0 表示不限 |

成员预算只在源文件显式设置时生效，成员表单没有预算项。团队 token 周期默认 24 小时，只定义统计窗口，不构成额度。达到显式上限时保留已有文字和文件、在线程通知负责人；周期额度或并发暂时不足时保留投递队列，恢复后继续准入。用量按 `ModelUsage` 回执结算，已开始的一次请求可能使结算值越过额度。

## 运行与边界

`research_team.py` 管理消息、上下文、成员收件箱和结算；`team_workflows.py` 在团队锁内调用纯规则引擎、保存状态并创建投递，提交后才执行。成员启动前重读文件，以当时的定义确定模型、工具权限和用户预算。

普通频道和私信成员在应用私有项目主工作树执行，与 `.ora/agents/` 和 `AGENTS.md` 共用文件；结束时保存检查点并附文件、提交引用。研究线程沿用绑定的实际目录或独立分叉工作树，详见 [文件夹工作区](folder-workspaces.md) 和 [研究分叉与合并](workspace-threads.md)。

团队接口只在本机版开放，并校验用户、团队、频道、成员、附件和线程归属。运行和工具入口再次检查权限与启停状态；停用取消待投递消息，删除保留历史身份。界面使用现有组件与 tokens，只保留简短标签和状态，中英文同步。
