## 按设计条目核对

| 条目 | 实现 |
| --- | --- |
| 1. 团队与导航 | 团队复用 ResearchWorkspace；团队切换器、频道、私信、线程、提及我的和通知铃铛接入研究侧栏。新研究按钮保留当前团队。 |
| 2. 默认频道与成员 | 建团队时创建综述、实验、写作、闲聊，以及研究者、导师、执行者、文献员、评审、写手、提炼者。旧团队首次读取时补齐。频道可新建、改名、归档。新增 librarian、reviewer、writer 三份角色 skill。 |
| 3. 消息与 @ | 频道消息持久化，普通频道没有自动回复；私信自动投递给对方。支持中文、英文角色名及角色标识的 @；补全支持方向键、Enter、Tab、Escape 和输入法组合输入。附件沿用所有者隔离的聊天上传接口。 |
| 4. 成员回应与过程 | 每次唤醒创建普通 Pi AgentRun，回应以成员身份出现；复用 RunTurn 的时间、工具步骤、输出和错误展示。普通聊天的能力清单不暴露团队专属工具。 |
| 5. 成员协作 | 回复正文及 team_send_message 的 @ 都能唤醒其他成员，后续回应归入同一线程。原研究轮次的消息、交接通过引用桥接参与接力，不复制研究正文。连续接力达到上限后发系统消息；研究者的新消息可开启下一段接力。 |
| 6. 线程与研究 | 右侧线程可关闭、全屏、收起，回复数从数据计算。研究通过虚拟根消息显示在实验频道，事件、轮次、节点、作业和继承历史直接适配现有数据。研究面板复用 ResearchProject / ThreadView；最新计划、结论卡片置顶，保留审批、实验、检查点、变更、分叉及合并入口。新研究流程发出后进入实验频道的研究线程。 |
| 7. 排队与立即发送 | 每个成员一个持久收件箱，同一成员同时只运行一项工作。Enter 默认排队，Cmd/Ctrl+Enter 立即发送；队列可编辑正文、撤回、改成立即发送。立即发送绑定原 AgentRun，经 AgentControl / Pi steer 投递；研究线程默认选择当前轮次的成员。跨频道插话完成后，结果引用发回发话位置。 |
| 8. 后台作业 | 每个完成作业使用唯一来源键发一条系统消息到研究线程。原 waiting_on、阶段推进和检查点机制保留，通知重试不重复发消息。 |
| 9. 状态与预算 | 私信列表和消息头像显示空闲、工作中、等你；计入研究轮次和普通成员运行的 tokens。成员默认上限 200 万，团队总上限 1200 万；预算用完停止新运行。 |
| 10. 通知与未读 | 新消息逐条记录已读；@研究者、参与线程的新回复、私信进入铃铛。频道已读不吞掉未展开的线程回复；运行中消息被读过后，最终回应完成会重新成为未读。旧研究继续使用原事件已读游标与决策通知。 |

所有新增团队接口通过现有本机版检查和工作区所有权检查。频道、线程、成员、作业和附件都不能跨团队或跨用户操作。发送请求带幂等标识；投递队列、运行引用和来源键持久化，服务重启可继续结算。

## 三个顺手修复

- Runner 中断显示退出码和 stderr 最后一行；父进程异常显示具体异常类型与末行原因，并遮蔽已知模型密钥。
- human_decision 中的回答正文以研究者消息显示，不再只有「已决定」。
- 交接的 summary、next_focus、needs_input、message、assessment 和最终回应规范化字面量 `\n`；已有数据在展示时同样规范化，后续检查点提交使用规范化后的交接。

## 与设计不同的实现及原因

- 排队保留在后端投递表，轮次结束后创建下一次 Pi 运行；没有提前塞进 Pi follow_up。这样在等待期间可可靠地编辑、撤回，并将每次投递与运行持久关联。立即发送仍用原生 steer。
- 实验频道可改名，暂不允许删除。旧研究直接投影到该频道，不增加每项旧研究的频道映射；其他频道删除采用归档，以保留历史和引用。
- 普通消息的「从这里分叉」以选中正文新建研究；研究轮次的代码分叉仍走原有检查点分叉。普通消息没有 Git 检查点。
- 简报采用项目概况、频道最近要点、最近 40 条上下文和长度边界，没有增加额外模型摘要调用。每次成员唤醒重建上下文，避免一个成员跨频道复用隐藏会话历史。
- 排队消息可改正文；改变 @ 收件人需要撤回后重发，避免已经投给其中一个成员后改写另一份收件内容。
- 频道和私信中的远端文件操作要求进入研究线程，复用现有远端工作区及实验机制；本机与托管团队可直接使用对应目录的文件工具。
- 成员配置和预算编辑界面不属于第 1 步；本步使用内置成员与固定默认预算。预算在运行准入处检查，已经开始的模型调用沿用原有机制结算，可能在结算时超过阈值。

## 负责人浏览器验收

Playwright 用例在 `frontend/e2e/screens/research-team.spec.ts`，本次只写用例，没有启动浏览器运行。

1. 创建团队和切换团队，确认 4 个频道、6 个 agent 私信及研究者身份；频道新建、改名、删除确认。
2. 频道发普通消息不唤醒成员；中英文 @ 补全、键盘选择、输入法回车；私信无 @ 直接回应，模型选择仅出现在私信。
3. Agent 回复展开工作过程、复制、从消息新建研究；打开线程、回复、全屏、收起、关闭；刷新和前进后退保持地址。
4. 同一成员工作时排队多条消息，编辑、撤回、改成立即发送；Cmd/Ctrl+Enter 确认插入原轮次；切到另一频道插话后，结果返回新位置。
5. Agent @ 接力、导师/执行者研究轮次 @ 文献员，确认正确线程和接力上限系统消息。
6. 新研究进入实验频道；旧研究完整展示，顶部计划和结论卡片可以操作，实验、日志、变更、分叉及合并仍可打开。
7. 长作业完成只发一次系统消息；waiting_on 继续推进研究；导师问题回答后显示研究者的原文回答。
8. 打开频道不会清除未展开线程的通知；看过运行中消息后离开，完成回应重新标为未读；@研究者及等你决策通知可跳转。
9. 浅色、深色、720px 窗口、长 Markdown、附件及键盘焦点；确认没有横向滚动，也没有说明性文案。
