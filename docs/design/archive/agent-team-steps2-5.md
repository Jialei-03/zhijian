# 研究团队 · 第 2–5 步

接在第 1 步（docs/design/archive/agent-team-step1.md）的成员、频道、消息、投递模型上。总设计见 docs/design/agent-team.md。

## 第 2 步：自定义成员
- 团队侧栏「成员」里可以添加、编辑、停用成员。字段：名字、头像（按名字自动生成，可换颜色）、角色说明（就是它的 skill，Markdown）、模型、工具权限（读文献 / 读写文件 / 运行命令和实验 / 使用的机器 / 只读）、每次被叫醒的预算（轮数、token）、默认在哪些频道里听（订阅）。
- 从内置成员复制一个再改；内置成员本身可以改模型和权限，不能删。
- 成员页：头像、名字、状态、最近在做什么、它参与的线程、花费。
- 简报里成员的角色说明放在最前面；工具按权限给。
- 一个成员可以同时出现在多个团队（全局成员库 + 团队里的成员实例），改库里的说明时询问是否同步到各团队。

## 第 3 步：工作流规则和列表视图
- 工作流 = 一组规则：触发（某频道或线程里出现某类消息 / 某成员发言 / @ 某人 / 作业结束 / 计划被批准 / 结论被提出 / 定时）→ 动作（叫醒某成员并附一句指示 / 交给某成员评审，不通过退回给谁，最多几次 / 停下来等我 / 发到某频道）。
- 团队有一个当前工作流，可以切换；内置：研究（现在的执行者 ↔ 导师流程）、文献综述、复现、写论文、从读到写（来自 docs/design/workflows.md 的内容，改写成规则）。上次做的线性工作流迁移成这里的模板。
- 现在硬编码的研究阶段推进（定题 → 实验 → 结论 → 复盘）改写成「研究」工作流的规则，行为不变；老研究照常推进。
- 定时任务成为规则的一种触发；定时任务分区保留，是规则的另一个入口。
- 列表视图：一条规则一行，「当 … 时 → … 做 …」，可编辑、启停、排序；规则触发时在消息上标注是哪条规则叫醒的。
- 防失控：每条规则有触发上限；团队有总预算；连续接力上限沿用第 1 步。

## 第 4 步：画布视图
- 工作流的另一种看法（同一份数据）：成员是节点，频道是大节点（黑板），规则是连线（交接、评审、订阅、等我、定时）。
- 拖线新建规则，点线编辑规则，拖节点排版（位置保存）；从左边栏拖入成员或频道。
- 运行时：节点上显示工作中 / 等你 / 空闲，连线上闪一下表示刚触发；点节点看它最近的消息。
- 用 React Flow（@xyflow/react，MIT）。键盘可操作，深浅色和窄窗口可用。

## 第 5 步：比较协作方式
- 在线程上「换个工作流再做一遍」：同一个问题，用另一套工作流（或改过的规则）开一个并行线程（复用分叉）。
- 比较视图：几个线程并排：结论、关键数字、花费（token、作业时间）、用时、轮数、成员参与情况。
- 评测项目里可以批量：一组问题 × 几套工作流，跑完出表。
