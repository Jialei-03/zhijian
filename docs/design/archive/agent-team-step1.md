# 研究团队 · 第 1 步：团队和消息

总设计见 docs/design/agent-team.md。这一步做出「像 Slack 一样和 agent 团队交流」的完整骨架，后面几步（自定义成员、工作流规则、画布、比较）都接在它上面。

## 要达到的效果
1. 进入研究分区，左侧是团队（就是项目）的 Slack 式侧栏：团队名（可切换团队）、频道、私信、「线程」「提及我的」。
2. 每个团队默认有频道 `#综述`、`#实验`、`#写作`、`#闲聊`（可增删改名），和内置成员：导师、执行者、文献员、评审、写手、提炼者（角色说明来自 agent-runtime/skills/research-*；文献员、评审、写手新写 skill）。我（研究者）也是成员。
3. 在频道或私信里发消息；`@成员` 叫醒那个 agent 来回应；不 @ 的消息：私信里由对方回应，频道里暂时没人自动接（工作流规则是第 3 步）。输入框支持 `@` 自动补全成员。
4. agent 回应是一条消息，作者是它；消息可以展开看工作过程（用时、步骤、改动），复用现在对话里轮次折叠和步骤显示的组件。
5. agent 能在回应里 `@` 别的成员，被 @ 的成员接着被叫醒（这就是协作）。为了防止互相 @ 停不下来：同一线程里 agent 之间连续接力超过 6 次就停下，发一条系统消息等我。
6. 任何消息可以开线程，线程在右侧打开（Slack 那样），也能全屏看。现有的每项研究就是一个线程：线程顶部置顶它的计划卡片和结论卡片，下面是它的对话、轮次、实验卡片、文件变更卡片（复用现在 ResearchProject / ThreadView 的内容和卡片）。在频道里「开始一项研究」，就是发一条消息并在它下面开研究线程（复用现在新建研究的流程）。
7. 发给正在工作的 agent：输入框给两种发送，回车「排队」（等它这一步做完再处理），⌘回车「立即发送」（steer：插进它正在进行的这一轮；运行器和 backend/agent_controls.py 已有 steer / follow_up）。排队的消息显示在输入框上方，可以编辑、撤回、改成立即发送。对没在工作的 agent 两者一样：直接叫醒。
8. 后台作业（实验）结束时，发一条系统消息到它所在的线程，并按现在的机制继续（研究线程里沿用 waiting_on 的轮次推进）。
9. 成员状态：空闲 / 工作中 / 等你，显示在私信列表和消息头像上。
10. 通知铃铛、未读圆点沿用现有的，但以消息为单位：@我的、等我决定的、我参与的线程有新回复。

## 数据和运行（实现由你决定，以下是约束）
- 团队 = 现有项目（ResearchWorkspace）。新增：成员、频道（含私信）、消息（含线程关系、@、类型和附带数据）、投递队列（排队 / 立即）。写 Alembic 迁移，接在最新的后面。
- 现有研究的数据不复制：研究线程里的消息从现有的研究事件、轮次、作业实时组装（适配层），新消息写进消息表。老数据不迁移也能完整显示。
- 叫醒一个 agent = 一次 Pi 运行（沿用 agent_worker 和 runner），简报里有：它的角色说明、所在频道或线程的上下文（长了就用摘要）、团队黑板摘要（各频道最近要点、进行中的研究）、谁 @ 了它要它做什么。工具：发消息（指定频道或线程、可以 @）、读频道、读线程、读团队概况，加上它的角色本来能用的工具（文献、文件、命令、实验）。在研究线程里，执行者和导师继续走现有的研究机制（阶段、轮次、地图、作业、检查点），它们说的话以成员身份出现在线程里。
- 同一个 agent 同一时间只做一件事，其余排队。预算按成员计，团队有总上限。
- 项目导师、项目对话、上次的主会话：并入这套。项目导师的能力分给导师成员；旧的项目对话显示成我和导师的私信历史。
- 所有接口只在本机版可用，沿用现有研究接口的权限检查；跨团队、跨用户隔离。

## 界面（遵守 docs/design/ui-norms.md）
- 布局：图标栏 | 团队侧栏 | 频道或私信的消息流 | 右侧线程面板（可关）。
- 消息流：作者头像和名字、时间、正文（Markdown）、卡片、回复数（点开线程）、悬停操作（回复、复制、从这里分叉、更多）。
- 输入框：`@` 补全，`+` 附件，回车排队 / ⌘回车立即发送（只在对方工作中时显示这个区别），模型选择只在私信里出现。
- 新研究页「想研究什么？」保留：发出后在 `#实验` 里建一条消息并开研究线程。
- 不写说明文字；空频道只有图标、频道名和输入框。
